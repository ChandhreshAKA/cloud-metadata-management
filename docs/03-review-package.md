# Selection engine review package

Generated by `scripts/make_review_package.py` from the code in this repository. **Every price, score and latency here is ILLUSTRATIVE (invented for demonstration).** Nothing below was typed by hand: the tables and JSON are the program's own output.

## 1. How to read this package

* The engine is the pure function `select(request, candidates, weights, policy)` in `app/selection/engine.py` (full source in section 6). There is **no `criteria.py`**: normalisation (`normalise`), constraints (`check_constraints`) and the cost calculation (`estimate_cost`) are all in `engine.py`; data types are in `models.py`.
* A candidate is a **provider-region**.
* Rounding: money to 8 decimals, normalised values and composites to 6 decimals, `ROUND_HALF_EVEN`, using `decimal.Decimal` (no floats).

"""Plain data types for the selection engine. No database, no I/O, no clock, no randomness.

All numbers are `decimal.Decimal` so results are exact and reproducible by hand.
GB means GiB (2^30 bytes) everywhere, matching sql/schema.sql.
"""

from __future__ import annotations

from dataclasses import dataclass, field
from decimal import Decimal

GIB = Decimal(1073741824)

# The five scored metrics, in the order used everywhere (and the order of the DB weight columns).
METRICS = ("storage_cost", "transfer_cost", "latency", "reliability", "security")
MINIMISED = frozenset({"storage_cost", "transfer_cost", "latency"})  # lower raw value is better
SECURITY_LEVELS = ("LOW", "MEDIUM", "HIGH")
TIERS = ("HOT", "COOL", "COLD", "ARCHIVE")

METRIC_LABELS = {
    "storage_cost": "storage cost",
    "transfer_cost": "transfer and request cost",
    "latency": "latency",
    "reliability": "reliability",
    "security": "security",
}


@dataclass(frozen=True)
class TierPricing:
    """ILLUSTRATIVE unless the source row says otherwise (see Candidate.is_illustrative)."""

    tier_code: str
    storage_usd_per_gb_month: Decimal
    retrieval_usd_per_gb: Decimal
    put_usd_per_1k: Decimal
    get_usd_per_1k: Decimal
    min_storage_days: int = 0


@dataclass(frozen=True)
class Candidate:
    """One provider-region that could hold the file, with the data the engine needs."""

    region_id: int
    provider_id: int
    provider_code: str
    provider_name: str
    region_code: str
    provider_active: bool
    region_active: bool
    health_status: str  # UP, DEGRADED, DOWN
    reliability_score: Decimal  # 0..10
    security_score: Decimal  # 0..10
    max_object_bytes: int
    egress_usd_per_gb: Decimal
    pricing: TierPricing | None  # price row for the requested tier; None = not priced
    latency_ms: Decimal | None  # typical GET latency; None = no measurement
    is_illustrative: bool = True

    @property
    def label(self) -> str:
        return f"{self.provider_name} ({self.region_code})"


@dataclass(frozen=True)
class FileRequest:
    file_size_bytes: int
    security_level: str
    expected_accesses_per_month: Decimal = Decimal(1)
    retention_months: Decimal = Decimal(12)
    tier: str = "HOT"

    def validate(self) -> None:

            raise ValueError("file_size_bytes must be >= 0")
        if self.security_level not in SECURITY_LEVELS:
            raise ValueError(f"security_level must be one of {', '.join(SECURITY_LEVELS)}")

            raise ValueError("retention_months must be > 0")

    transfer_cost: Decimal
    latency: Decimal
    reliability: Decimal

### `app/selection/engine.py`

```python
"""The provider selection engine: a pure function.

    select(request, candidates, weights, policy) -> SelectionResult

It reads nothing and writes nothing: no database, no files, no clock, no randomness. The same
inputs always give the same output, which is what makes it testable by hand and reusable by
upload (chunk 4), replica placement (chunk 5) and savings estimates (chunk 6).

PROCESS
  1. Hard constraints (before any ranking). A candidate is rejected if any of these fail, and
     EVERY failing reason is recorded:
       provider enabled, region enabled, not DOWN, priced for the requested tier, has a latency
       measurement, file size <= provider limit, security score >= minimum for the file's
       security level, reliability score >= minimum for that level.
     Size fit is a hard filter, never a scored criterion.
  2. Cost for THIS file, per candidate (money rounded to 8 decimals, ROUND_HALF_EVEN):
       size_gb        = file_size_bytes / 2^30
       billed_months  = max(retention_months, min_storage_days / 30)
       reads          = expected_accesses_per_month * retention_months
       storage_cost   = size_gb * storage_usd_per_gb_month * billed_months
       request_cost   = put_usd_per_1k / 1000 * 1  +  get_usd_per_1k / 1000 * reads
       retrieval_cost = size_gb * retrieval_usd_per_gb * reads
       egress_cost    = size_gb * egress_usd_per_gb * reads
       transfer_cost  = request_cost + retrieval_cost + egress_cost
       total_cost     = storage_cost + transfer_cost
  3. Five metrics: storage_cost, transfer_cost, latency (minimised); reliability, security
     (maximised). Min-max normalise each across the ELIGIBLE candidates only:
       n = (x - min) / (max - min), rounded to 6 decimals (ROUND_HALF_EVEN).
     ZERO RANGE (max == min: all equal, or a single candidate): there is nothing to compare, so
     every candidate gets score 1.0 on that metric (n is reported as 0 for minimised metrics and
     1 for maximised ones, so that score = 1 - n or n still holds). No division by zero occurs.
  4. Direction: score = 1 - n for minimised metrics, score = n for maximised. Higher is better.
  5. composite = sum(weight * score), rounded to 6 decimals. Weights are validated (>= 0) and
     must sum to 1; app.selection.presets.resolve_weights normalises and reports it if not.
  6. Ranking uses the ROUNDED composite, then ties are broken in this fixed order:
       higher security score, higher reliability score, lower total cost,
       lower provider_id, lower region_id.
"""

from __future__ import annotations

from collections.abc import Iterable, Mapping
from decimal import ROUND_HALF_EVEN, Decimal, localcontext

from app.selection import explain
from app.selection.models import (
    GIB,
    METRICS,
    MINIMISED,
    Candidate,
    CostBreakdown,
    FileRequest,
    Policy,
    RankedCandidate,
    Rejection,
    SelectionResult,
    Weights,
)

MONEY_QUANTUM = Decimal("0.00000001")  # 8 decimals
SCORE_QUANTUM = Decimal("0.000001")  # 6 decimals
_PRECISION = 40
COST_FORMULA = (
    "size_gb = file_size_bytes / 2^30",
    "billed_months = max(retention_months, min_storage_days / 30)",
    "reads = expected_accesses_per_month * retention_months",
    "storage_cost = size_gb * storage_usd_per_gb_month * billed_months",
    "request_cost = put_usd_per_1k / 1000 * 1 + get_usd_per_1k / 1000 * reads",
    "retrieval_cost = size_gb * retrieval_usd_per_gb * reads",
    "egress_cost = size_gb * egress_usd_per_gb * reads",
    "transfer_cost = request_cost + retrieval_cost + egress_cost",
    "total_cost = storage_cost + transfer_cost",
    "money is rounded to 8 decimals; normalised values and composites to 6 (half-even)",
)
TIE_BREAK_ORDER = (
    "higher composite (rounded to 6 decimals)",
    "higher security score",
    "higher reliability score",
    "lower total cost",
    "lower provider_id",
    "lower region_id",
)


def _money(value: Decimal) -> Decimal:
    return value.quantize(MONEY_QUANTUM, rounding=ROUND_HALF_EVEN)


def estimate_cost(request: FileRequest, candidate: Candidate) -> CostBreakdown:
    """Cost of storing and serving THIS file at `candidate` (formulas in the module docstring)."""
    pricing = candidate.pricing
    if pricing is None:
        raise ValueError(f"{candidate.label} has no pricing for tier {request.tier}")
    with localcontext() as ctx:
        ctx.prec = _PRECISION
        size_gb = Decimal(request.file_size_bytes) / GIB
        billed_months = max(request.retention_months, Decimal(pricing.min_storage_days) / 30)
        reads = request.expected_accesses_per_month * request.retention_months
        storage = size_gb * pricing.storage_usd_per_gb_month * billed_months
        requests = pricing.put_usd_per_1k / 1000 * 1 + pricing.get_usd_per_1k / 1000 * reads
        retrieval = size_gb * pricing.retrieval_usd_per_gb * reads
        egress = size_gb * candidate.egress_usd_per_gb * reads
        return CostBreakdown(
            size_gb=size_gb,
            billed_months=billed_months,
            reads=reads,
            storage=_money(storage),
            request=_money(requests),
            retrieval=_money(retrieval),
            egress=_money(egress),
        )


def check_constraints(request: FileRequest, candidate: Candidate, policy: Policy) -> list[str]:
    """Every hard constraint the candidate fails (empty list = eligible)."""
    reasons: list[str] = []
    if not candidate.provider_active:
        reasons.append("provider is disabled")
    if not candidate.region_active:
        reasons.append("region is disabled")
    if candidate.health_status == "DOWN":
        reasons.append("provider-region is currently DOWN")
    if candidate.pricing is None:
        reasons.append(f"no {request.tier} pricing is registered")
    if candidate.latency_ms is None:
        reasons.append("no latency measurement is available")
    if request.file_size_bytes > candidate.max_object_bytes:
        reasons.append(
            f"file size {request.file_size_bytes} bytes exceeds the provider limit "
            f"{candidate.max_object_bytes} bytes"
        )
    min_security = policy.min_security[request.security_level]
    if candidate.security_score < min_security:
        reasons.append(
            f"security score {explain.fmt(candidate.security_score)} is below the "
            f"{request.security_level} minimum {explain.fmt(min_security)}"
        )
    min_reliability = policy.min_reliability[request.security_level]
    if candidate.reliability_score < min_reliability:
        reasons.append(
            f"reliability score {explain.fmt(candidate.reliability_score)} is below the "
            f"{request.security_level} minimum {explain.fmt(min_reliability)}"
        )
    return reasons


def normalise(
    values: Mapping[int, Decimal], *, minimise: bool
) -> tuple[dict[int, Decimal], dict[int, Decimal]]:
    """Min-max normalise. Returns (normalised, score); score is higher-is-better.

    Zero range gives every key score 1 (see module docstring), never a division by zero.
    """
    if not values:
        return {}, {}
    low, high = min(values.values()), max(values.values())
    if high == low:
        best = Decimal(0) if minimise else Decimal(1)
        return {k: best for k in values}, {k: Decimal(1) for k in values}
    with localcontext() as ctx:
        ctx.prec = _PRECISION
        norm = {
            k: ((v - low) / (high - low)).quantize(SCORE_QUANTUM, rounding=ROUND_HALF_EVEN)
            for k, v in values.items()
        }
    score = {k: (Decimal(1) - n) if minimise else n for k, n in norm.items()}
    return norm, score


def _sort_key(item: tuple[Candidate, CostBreakdown, Decimal]):
    candidate, cost, composite = item
    return (
        -composite,
        -candidate.security_score,
        -candidate.reliability_score,
        cost.total,
        candidate.provider_id,
        candidate.region_id,
    )


def select(
    request: FileRequest,
    candidates: Iterable[Candidate],
    weights: Weights,
    policy: Policy,
    *,
    weights_note: str | None = None,
    preset_name: str | None = None,
) -> SelectionResult:
    request.validate()
    ordered = sorted(candidates, key=lambda c: (c.provider_id, c.region_id))

    eligible: list[Candidate] = []
    rejected: list[Rejection] = []
    for candidate in ordered:
        reasons = check_constraints(request, candidate, policy)
        if reasons:
            rejected.append(Rejection(candidate, tuple(reasons)))
        else:
            eligible.append(candidate)

    costs = {c.region_id: estimate_cost(request, c) for c in eligible}
    raw: dict[int, dict[str, Decimal]] = {
        c.region_id: {
            "storage_cost": costs[c.region_id].storage,
            "transfer_cost": costs[c.region_id].transfer,
            "latency": c.latency_ms,  # type: ignore[dict-item]  (None was rejected above)
            "reliability": c.reliability_score,
            "security": c.security_score,
        }
        for c in eligible
    }
    norm: dict[str, dict[int, Decimal]] = {}
    score: dict[str, dict[int, Decimal]] = {}
    for metric in METRICS:
        norm[metric], score[metric] = normalise(
            {rid: values[metric] for rid, values in raw.items()}, minimise=metric in MINIMISED
        )

    weight_of = weights.as_dict()
    scored: list[tuple[Candidate, CostBreakdown, Decimal]] = []
    contributions: dict[int, dict[str, Decimal]] = {}
    for c in eligible:
        parts = {m: weight_of[m] * score[m][c.region_id] for m in METRICS}
        contributions[c.region_id] = parts
        with localcontext() as ctx:
            ctx.prec = _PRECISION
            total = sum(parts.values(), Decimal(0))
        scored.append((c, costs[c.region_id], total.quantize(SCORE_QUANTUM, ROUND_HALF_EVEN)))
    scored.sort(key=_sort_key)

    ranked = tuple(
        RankedCandidate(
            rank=position,
            candidate=c,
            cost=cost,
            raw=raw[c.region_id],
            normalised={m: norm[m][c.region_id] for m in METRICS},
            score={m: score[m][c.region_id] for m in METRICS},
            contribution=contributions[c.region_id],
            composite=composite,
        )
        for position, (c, cost, composite) in enumerate(scored, start=1)
    )

    advantages: tuple[str, ...] = ()
    disadvantages: tuple[str, ...] = ()
    if len(ranked) >= 2:
        adv, dis = explain.compare_metrics(ranked[0], ranked[1])
        advantages, disadvantages = tuple(adv), tuple(dis)

    warnings: list[str] = []
    if any(c.is_illustrative for c in eligible):
        warnings.append(
            "Prices, scores and latencies are ILLUSTRATIVE simulation values, not vendor data."
        )
    if weights_note:
        warnings.append(weights_note)
    if ranked and ranked[0].candidate.health_status == "DEGRADED":
        warnings.append("The selected provider-region is currently DEGRADED.")

    return SelectionResult(
        request=request,
        weights=weights,
        weights_note=weights_note,
        ranked=ranked,
        rejected=tuple(rejected),
        selected=ranked[0] if ranked else None,
        advantages=advantages,
        disadvantages=disadvantages,
        explanation=explain.build_explanation(
            request, weights, preset_name, ranked, tuple(rejected)
        ),
        warnings=tuple(warnings),
    )


def compare_presets(
    request: FileRequest,
    candidates: Iterable[Candidate],
    presets: Mapping[str, Weights],
    policy: Policy,
) -> dict[str, SelectionResult]:
    """Run the same request under every preset (used to show that weights change the winner)."""
    pool = list(candidates)
    return {
        name: select(request, pool, weights, policy, preset_name=name)
        for name, weights in presets.items()
    }
```

### `app/selection/presets.py`

```python
"""Weight presets and weight validation.

PRESETS mirrors the rows inserted by sql/seed_data.sql into weight_profiles (the database is the
source of truth at run time; a unit test keeps this copy and the SQL in agreement). The
engine itself never reads the database: callers pass a Weights object in.

Names: COST_SAVER = cost-focused, PERFORMANCE = performance-focused, SECURE = security-focused.
"""

from __future__ import annotations

from collections.abc import Mapping
from decimal import Decimal, InvalidOperation

from app.selection.models import METRICS, Policy, Weights

DEFAULT_PRESET = "BALANCED"

PRESETS: dict[str, Weights] = {
    "BALANCED": Weights(
        Decimal("0.25"), Decimal("0.15"), Decimal("0.20"), Decimal("0.25"), Decimal("0.15")
    ),
    "COST_SAVER": Weights(
        Decimal("0.40"), Decimal("0.20"), Decimal("0.10"), Decimal("0.20"), Decimal("0.10")
    ),
    "PERFORMANCE": Weights(
        Decimal("0.10"), Decimal("0.10"), Decimal("0.50"), Decimal("0.20"), Decimal("0.10")
    ),
    "SECURE": Weights(
        Decimal("0.10"), Decimal("0.05"), Decimal("0.10"), Decimal("0.25"), Decimal("0.50")
    ),
}

# Used when system_config has no override. security.min_score.* values equal those seeded by
# sql/seed_data.sql; the reliability minimums are chosen for the illustrative seed scores
# (sql/seed_selection_config.sql stores them so they can be changed without a code edit).
DEFAULT_POLICY = Policy(
    min_security={"LOW": Decimal("0"), "MEDIUM": Decimal("8.0"), "HIGH": Decimal("9.2")},
    min_reliability={"LOW": Decimal("0"), "MEDIUM": Decimal("9.0"), "HIGH": Decimal("9.4")},
)

_TOLERANCE = Decimal("0.0000001")


class WeightError(ValueError):
    """Weights are invalid (negative, not a number, unknown metric, or all zero)."""


def _to_decimal(metric: str, value: object) -> Decimal:
    try:
        number = Decimal(str(value))
    except (InvalidOperation, ValueError) as exc:
        raise WeightError(f"weight for {metric} is not a number") from exc
    if not number.is_finite():
        raise WeightError(f"weight for {metric} is not a finite number")
    if number < 0:
        raise WeightError(f"weight for {metric} is negative")
    return number


def resolve_weights(
    base: Weights, overrides: Mapping[str, object] | None = None
) -> tuple[Weights, str | None]:
    """Apply per-request overrides on top of `base`, validate, and normalise if needed.

    * Unknown metric names, negative or non-numeric values raise WeightError.
    * The result must sum to 1. If it does not (for example you override one weight and leave
      the rest), the weights are DIVIDED BY THEIR SUM and the returned note says so.
    * If the weights add up to 0 they cannot be normalised: WeightError.
    """
    merged = base.as_dict()
    for metric, raw in (overrides or {}).items():
        if metric not in METRICS:
            raise WeightError(f"unknown weight '{metric}' (expected one of {', '.join(METRICS)})")
        merged[metric] = _to_decimal(metric, raw)
    for metric in METRICS:  # also validates the base weights
        merged[metric] = _to_decimal(metric, merged[metric])

    total = sum(merged.values(), Decimal(0))
    if total == 0:
        raise WeightError("weights must not all be zero")
    note = None
    if abs(total - 1) > _TOLERANCE:
        merged = {m: v / total for m, v in merged.items()}
        shown = format(total.normalize(), "f")
        note = f"weights summed to {shown}, so each was divided by {shown} to sum to 1"
    return Weights(**{m: merged[m] for m in METRICS}), note
```

### `app/selection/explain.py`

```python
"""Turn engine numbers into advantages, disadvantages and a plain-English explanation.

Pure text generation from values already computed by the engine; nothing here decides anything.
"""

from __future__ import annotations

from decimal import Decimal

from app.selection.models import (
    METRIC_LABELS,
    METRICS,
    MINIMISED,
    FileRequest,
    RankedCandidate,
    Rejection,
    Weights,
)

_UNIT = {
    "storage_cost": "$",
    "transfer_cost": "$",
    "latency": " ms",
    "reliability": "",
    "security": "",
}


def fmt(value: Decimal) -> str:
    """Plain decimal text without exponent or trailing zeros (0.50 -> 0.5, 100 -> 100)."""
    text = format(value.normalize(), "f")
    return text


def _show(metric: str, value: Decimal) -> str:
    if metric in ("storage_cost", "transfer_cost"):
        return f"${fmt(value)}"
    return f"{fmt(value)}{_UNIT[metric]}"


def compare_metrics(winner: RankedCandidate, other: RankedCandidate) -> tuple[list[str], list[str]]:
    """Per-metric advantages and disadvantages of `winner` relative to `other`."""
    advantages: list[str] = []
    disadvantages: list[str] = []
    for metric in METRICS:
        a, b = winner.raw[metric], other.raw[metric]
        if a == b:
            continue
        better = (a < b) if metric in MINIMISED else (a > b)
        diff = abs(a - b)
        word = (
            ("lower" if metric in MINIMISED else "higher")
            if better
            else ("higher" if metric in MINIMISED else "lower")
        )
        line = (
            f"{METRIC_LABELS[metric]}: {_show(metric, a)} vs {_show(metric, b)} "
            f"({_show(metric, diff)} {word})"
        )
        (advantages if better else disadvantages).append(line)
    return advantages, disadvantages


def describe_weights(weights: Weights) -> str:
    return ", ".join(f"{METRIC_LABELS[m]} {fmt(getattr(weights, m))}" for m in METRICS)


def build_explanation(
    request: FileRequest,
    weights: Weights,
    preset_name: str | None,
    ranked: tuple[RankedCandidate, ...],
    rejected: tuple[Rejection, ...],
) -> str:
    sentences: list[str] = []
    if not ranked:
        sentences.append(
            f"No provider-region can store this {request.security_level}-security file of "
            f"{request.file_size_bytes} bytes in tier {request.tier}."
        )
    else:
        winner = ranked[0]
        basis = f"the {preset_name} weights" if preset_name else "custom weights"
        sentences.append(
            f"Selected {winner.candidate.label} with a composite score of {fmt(winner.composite)} "
            f"using {basis} ({describe_weights(weights)})."
        )
        if len(ranked) == 1:
            sentences.append(
                "It is the only provider-region that passed the hard constraints, so every metric "
                "scores 1.0 by definition and no comparison was needed."
            )
        else:
            runner = ranked[1]
            margin = winner.composite - runner.composite
            sentences.append(
                f"Runner-up: {runner.candidate.label} with {fmt(runner.composite)} "
                f"({fmt(margin)} behind)."
            )
            diffs = {m: winner.contribution[m] - runner.contribution[m] for m in METRICS}
            leads = sorted((m for m in METRICS if diffs[m] > 0), key=lambda m: (-diffs[m], m))
            lags = sorted((m for m in METRICS if diffs[m] < 0), key=lambda m: (diffs[m], m))
            if leads:
                sentences.append(
                    "The lead comes from "
                    + ", ".join(f"{METRIC_LABELS[m]} (+{fmt(diffs[m])})" for m in leads[:3])
                    + "."
                )
            if lags:
                sentences.append(
                    f"{runner.candidate.label} is better on "
                    + ", ".join(f"{METRIC_LABELS[m]} ({fmt(-diffs[m])} of score)" for m in lags[:3])
                    + ", which was not enough to overcome the lead."
                )
            cheapest = min(ranked, key=lambda r: (r.cost.total, r.candidate.provider_id))
            if cheapest is winner:
                sentences.append("It is also the cheapest eligible option.")
            else:
                extra = winner.cost.total - cheapest.cost.total
                sentences.append(
                    f"It is NOT the cheapest eligible option: {cheapest.candidate.label} costs "
                    f"${fmt(cheapest.cost.total)} over {fmt(request.retention_months)} months "
                    f"versus ${fmt(winner.cost.total)} (${fmt(extra)} more for the winner) but "
                    f"ranked #{cheapest.rank} because the other metrics, weighted as above, "
                    "outweighed price."
                )
    for rejection in rejected:
        sentences.append(f"Excluded {rejection.candidate.label}: {'; '.join(rejection.reasons)}.")
    return " ".join(sentences)
```

### `app/selection/baselines.py`

```python
"""Baselines for the evaluation chapter: what simpler strategies would have chosen.

Both baselines respect the SAME hard constraints as the engine, so a comparison never "wins" by
breaking a security or size rule. They are pure functions like the engine.

  cheapest_only : the eligible candidate with the lowest total cost for this file
                  (ties: lower provider_id, then lower region_id). Ignores latency,
                  reliability and security beyond the hard minimums.
  fixed_provider: always the named provider (its best-eligible region by lowest provider/region
                  id), whatever the alternatives. If that provider fails a constraint, the
                  baseline reports that it cannot be used and why.
"""

from __future__ import annotations

from collections.abc import Iterable

from app.selection.engine import check_constraints, estimate_cost
from app.selection.models import BaselineResult, Candidate, FileRequest, Policy


def cheapest_only(
    request: FileRequest, candidates: Iterable[Candidate], policy: Policy
) -> BaselineResult:
    request.validate()
    eligible = [c for c in candidates if not check_constraints(request, c, policy)]
    if not eligible:
        return BaselineResult("cheapest_only", None, None, "no eligible provider-region")
    priced = [(estimate_cost(request, c), c) for c in eligible]
    cost, winner = min(priced, key=lambda p: (p[0].total, p[1].provider_id, p[1].region_id))
    return BaselineResult("cheapest_only", winner, cost, "lowest total cost among eligible")


def fixed_provider(
    request: FileRequest, candidates: Iterable[Candidate], policy: Policy, provider_code: str
) -> BaselineResult:
    request.validate()
    own = sorted(
        (c for c in candidates if c.provider_code == provider_code),
        key=lambda c: (c.provider_id, c.region_id),
    )
    if not own:
        return BaselineResult("fixed_provider", None, None, f"unknown provider {provider_code}")
    reasons: list[str] = []
    for candidate in own:
        failed = check_constraints(request, candidate, policy)
        if not failed:
            return BaselineResult(
                "fixed_provider",
                candidate,
                estimate_cost(request, candidate),
                f"always {provider_code}",
            )
        reasons.append(f"{candidate.label}: {'; '.join(failed)}")
    return BaselineResult(
        "fixed_provider",
        None,
        None,
        f"{provider_code} cannot store this file ({' | '.join(reasons)})",
    )
```

## 7. Direct answers to the logic questions

| Question | Answer | Where in the code | Test that proves it |
|---|---|---|---|
| Does min-max use only eligible providers? | **Yes.** `check_constraints` runs first and splits `eligible` from `rejected`; `raw`, `normalise` and ranking are built from `eligible` only. A DOWN provider with extreme values does not change the others' scores. | `select()`, loops over `eligible` | `test_rejected_candidates_never_take_part_in_ranking_or_normalisation`; case B above equals case A |
| Are cost and latency inverted? | **Yes.** `normalise(..., minimise=True)` gives `score = 1 - n` for storage cost, transfer cost and latency; reliability and security use `score = n`. A higher composite is always better. | `normalise()` and `MINIMISED` in `models.py` | `test_minimised_metric_gives_best_value_score_one_and_worst_zero`, `test_maximised_metric_gives_highest_value_score_one`, and the worked example |
| Zero-range case? | When `max == min` (all equal, or one candidate) **every candidate scores 1.0** on that metric; no division happens. `n` is reported as 0 (minimised) or 1 (maximised). | `normalise()`, the `if high == low` branch | `test_all_equal_values_do_not_divide_by_zero_and_everyone_scores_one`, `test_single_candidate_scores_one` |
| Is the tie-break deterministic? | **Yes.** Sort key: higher rounded composite, higher security, higher reliability, lower total cost, lower provider_id, lower region_id. Candidates are first sorted by (provider_id, region_id), so input order never matters. No randomness anywhere. | `_sort_key`, `select()` | `test_tie_break_order_security_then_reliability_then_cost_then_ids`, `test_results_do_not_depend_on_the_order_candidates_are_supplied` (25 shuffles) |
| Is size fit scored? | **No**, it is a hard constraint. | `check_constraints()` | `test_size_fit_is_a_hard_filter_not_a_score` |
| Are weights validated? | Non-negative, finite, known names, not all zero; if they do not sum to 1 they are divided by their sum and a note says so. | `presets.resolve_weights` | `test_invalid_weights_are_rejected`, `test_override_is_applied_then_normalised_and_the_note_says_so` |

## 8. Known properties a reviewer should be aware of

* **Rank reversal:** min-max scores depend on the set of eligible candidates, so adding or removing a provider can change relative scores of the others.
* The composite is rounded to 6 decimals **before** ranking, so near-equal composites tie and fall to the tie-break order.
* Latency is the median of the latest 20 successful GET probes per region; in the seed these are simulated values.
* Reads are assumed to download the whole file; one PUT per upload; egress price is per region.
